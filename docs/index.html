MusicD

A self-hosted music server for one library and one home network

MusicD Server scans your albums into SQLite, serves a Roon-inspired mobile-first web app, and plays to DLNA / UPnP, Sonos, Squeezelite and local USB DACs — with parametric EQ, AutoEQ presets, FIR convolution and a per-stream signal path you can actually read.

v1.1.7.0 Node 20 · Express · SQLite React SPA · PWA Docker · port 32700 MIT licence

What’s new in 1.1.7.0

Sonos bonded sets stop lying about how many speakers you have, the share card gets rebuilt, and the trial gate is gone.

Fixed

⬇️In-app updates install, not just download

An update would download and then stop with Cannot resolve host path for /mnt/musicd_updates. Installing is done by a short-lived sidecar container that reads the staged tarball from the host side, so that directory has to be a real bind mount — and the shortened docker run here had dropped it, leaving it inside the container with no host path to resolve.

The command above now includes -v /var/lib/musicd-server-v1/updates:/mnt/musicd_updates and creates the directory before the chown so it belongs to UID 1000. A named volume will not work — it has no host path either. The error now names the missing mount and the flag to add.

Fixed

📱Correct layout as an iPhone home-screen app

Content sat below a reserved band instead of running under the status bar, and the controls along the top were pushed out of reach. Two causes: apple-mobile-web-app-status-bar-style: black-translucent shifts the document up without growing the layout viewport, leaving a gap the size of the top inset at the bottom; and the shell measured itself in 100vh, which disagrees with the physical display under viewport-fit=cover.

The head now matches MusicD-Remote, the build confirmed correct on a device, and every screen pads itself with env(safe-area-inset-*) — seventeen surfaces across twelve files — rather than the app shell reserving a band for all of them.

iOS caches the window configuration when you add the shortcut, not per launch, so delete the home-screen shortcut and add it again after updating — otherwise the old window persists whatever the server sends.

Fixed

🔊Sonos stereo pairs play as one speaker

Every ZonePlayer answers SSDP for itself, so a bonded pair of Fives registered as two renderers with the same name — and only one of them worked. The other was the bonded satellite: it answers discovery but rejects SetAVTransportURI, because in a bonded set only the coordinator drives playback.

Discovery now queries ZoneGroupTopology and registers coordinators only. Three firmware representations of a bonded set are handled — an Invisible="1" member, a satellite named only in the coordinator’s ChannelMapSet, and home-theatre sets using nested <Satellite> elements with HTSatChanMapSet. The query fails open: if no speaker answers, every speaker is registered exactly as before.

Changed

🏠Sonos renderers named from the room

Display names now come from the topology’s ZoneName as Room - Model — “Living Room - Sonos Five” — instead of being derived from the verbose UPnP friendly name. Rename a room in the Sonos app and it is picked up on the next discovery sweep.

Rooms grouped in the Sonos app collapse to a single renderer, driven by the group coordinator, matching how the Sonos app shows a group. While grouped, the volume control targets the coordinator’s room rather than the whole group; ungrouping restores the separate renderer.

Changed

🖼️Redesigned share card

The card is now 1200 × 600 with the album art full-bleed across the entire left half and the release year, title and artist centred in the right half — replacing the 1200 × 720 layout with inset art, a blurred backdrop and genre pills.

There is no measureText server-side, so text metrics are estimated from the DejaVu hmtx tables, calibrated never to under-measure: long titles shrink or wrap one step early rather than overrunning the card. fonts-dejavu-core is now installed explicitly in the image, so cards can no longer rasterise as empty boxes.

New

📤Share button on Now Playing

The full-screen player had no way to share; it now has one beside the signal-path orb. It fetches the rendered card, previews it in a bottom sheet, and hands the PNG to the system share sheet via the Web Share API, falling back to a download where that is unavailable. Dismissing the iOS sheet is treated as “no thanks”, not an error.

New

🎚️Discrete volume buttons

Circular − and + controls sit at the right end of the volume slider, stepping by 5 and clamped to 0–100. They route through the same handler the slider uses, so drag behaviour is unchanged.

The volume bar also now clears env(safe-area-inset-bottom) plus a 44px gap, so dragging it no longer fights the iOS home-indicator swipe.

Changed

🔓Stable is the baseline tier

Every install starts on Stable instead of Demo. There is no trial gate and no album cap — the baseline tier is the floor, and no install can sit below it. Baseline no longer depends on the update manifest either.

The four 4-digit access codes are unchanged, and now do one job only: opting a machine into the Early Access, Beta or Internal update channels.

Features

One server, one library, one home network. Everything below runs on your own hardware and talks to nothing you did not ask it to.

Playback & formats

🎵Codecs

Scanned and played straight from disk:

  • Lossless — FLAC, WAV, AIFF, ALAC (.m4a), WavPack (.wv)
  • Lossy — MP3, Ogg Vorbis, Opus, AAC (.m4a)
  • DSD — .dsf, .dff, .dsd

FLAC, MP3 and WAV pass through untouched when nothing in the chain needs to alter them — no volume levelling, no DSP, no downsample.

〰️DSD handling

DSD bitstreams are decoded by FFmpeg and resampled to 176.4 kHz PCM — the highest 44.1-family integer multiple at or below 192 kHz. Going to 192 kHz would force a 44.1 ↔ 48 conversion, which is audibly worse, and 176.4 stays inside the bandwidth ceiling of every renderer that matters.

Local ALSA output additionally has a per-DAC DSD mode setting.

📶Gapless

The next track is pre-queued on the renderer through the UPnP-standard SetNextAVTransportURI while the current one is still playing, and the queued target is cleared on a skip so it cannot leak into the new selection.

📉Volume levelling

Per-track and per-album loudness normalisation against a configurable LUFS target (default −18 LUFS), analysed with loudgain (libebur128) and falling back to FFmpeg. Existing R128 tags are honoured with their own reference level.

🌡️CPU thermal throttling

Background loudness and metadata jobs back off against a user-configured CPU temperature ceiling (default 65 °C), read from the host’s /sys/class/thermal with sensor selection across x86_pkg_temp, coretemp, k10temp and cpu_thermal.

📻Radio mode

When the queue runs dry, radio mode keeps going instead of stopping, with a short history so it does not immediately repeat itself.

Renderers & zones

🛰️DLNA / UPnP

Any AVTransport renderer, auto-discovered over SSDP. This is the widest-compatibility path and the one DSP applies to.

🎶Sonos

Native integration built on raw SOAP, topology-aware since 1.1.3.8 so pairs, bonded subs and surrounds, and app-side groups each appear once. An optional 16-bit force mode exists for stubborn zones, using triangular (TPDF) dither on the way down.

🔗Squeezelite / LMS

Squeezebox sink discovery and control, with an optional Lyrion Media Server bridge configured through LMS_HOST and LMS_PORT. DSP applies here too.

🎧USB DAC via ALSA

Local output with capability detection, per-device DSD mode, and a DSP bypass that is on by default so a DAC doing its own processing is not doubled up. Capabilities are probed lazily via aplay --dump-hw-params when /proc/asound is not available.

🏘️Multi-zone

Each zone is one renderer with its own queue, position and volume, all running at once. The UI focuses one zone at a time; the others keep playing. Per-zone queue and position survive a server restart.

DSP

🎛️Parametric EQ

Biquad bands per profile — peaking, low shelf and high shelf — compiled into an FFmpeg filter chain per stream. Profiles are assigned per renderer, so your headphone amp and your living-room speakers do not share an EQ.

📚AutoEQ presets

A starter set of 22 headphone presets ships in the image. One action in Settings pulls the full AutoEQ parametric database — thousands of measured models — straight from the upstream AutoEq project and rebuilds the local index.

🌀FIR convolution

Upload impulse-response WAVs, one per supported sample rate, with independent dry and wet gain. Malformed IRs are rejected with an actual explanation rather than silence.

🎚️Crossfeed & headroom

Crossfeed profiles cmoy, meier and jmeier via bs2b, plus a manual headroom slider from −12 dB to 0 dB (default −3 dB) at the end of the chain.

🛡️Auto-preamp

The maximum gain the PEQ chain can apply is computed when the profile is saved and negated into a preamp, keeping peaks at or under 0 dBFS without you doing arithmetic.

🔁Chain order

Fixed and inspectable:

  • source → auto-preamp → PEQ
  • → convolution → crossfeed
  • → downsample → dither

DSP is applied for DLNA and Squeezelite renderers. Sonos zones keep their stored profile but are not processed, because Sonos runs its own EQ.

Signal path

🔍Per-play signal path

A Roon-style chain is built for every play and pushed to the client with the rest of the player state, reachable from the orb in the full-screen player. It shows what actually happened to the stream on the way to that specific renderer — decode, EQ, resampling and the renderer itself — rather than what the file claims on disk.

🚚Transcoding & streaming

A real-time FFmpeg pipeline downsamples to the renderer’s maximum supported rate, dithers on bit-depth reduction, and reports the chosen output rate back on the response. Diagnostic headers are ASCII-sanitised so a stray em dash cannot kill the stream mid-play.

Library, search & Focus

🗂️Scanning

Auto-scan on startup plus a filesystem watcher, which polls by default because inotify does not propagate across Docker bind mounts and NFS / SMB shares. Multi-disc albums are flattened — CD1, CD2, Disc 2 folders group into one album.

🔎Search

SQLite FTS5 across title, artist, album and genre, indexed in the same database as everything else.

🎯Focus filters

Roon-style include and exclude pills, ANDed across sub-sections and ORed within one:

  • Format, genre, decade, artist
  • Bit depth, sample rate, channel count
  • Last played, added on

Combinations you keep reaching for can be saved and re-applied.

🏷️Tags & bookmarks

User tags with hex colours, applied to albums and tracks, plus a save-for-later flag on both that is deliberately separate from tags — it is a pinned bookmark, not a label.

Metadata & discovery

🖼️Cover art

Embedded artwork and folder images (cover, folder, front…) first, then Cover Art Archive via the matched MusicBrainz release. Results are cached on disk and in a bounded in-memory LRU.

🧬MusicBrainz & AcoustID

Album and artist matching against MusicBrainz release-groups, run by a scheduler and throttled to the 1 req/s their terms require. For files too poorly tagged to match, fpcalc generates an acoustic fingerprint and looks it up against AcoustID.

✍️Bios & logos

Artist biographies from Last.fm, cached locally. Artist logos come from a waterfall — MusicBrainz ID, then fanart.tv, then TheAudioDB, then a typographic SVG rendered on the server so there is always something to show.

📰Music news

An in-app feed built from Pitchfork’s RSS channels plus Qobuz Magazine and Bandcamp Daily, rate-limited so a client stuck in a refresh loop cannot hammer anyone’s server.

Sharing & integrations

🪪Share cards

1200 × 600 PNGs rendered server-side from SVG with sharp — one for the current track, one for any album. Shared from the full-screen player or an album page through the system share sheet.

📊Last.fm scrobbling

Per-zone now-playing updates and scrobbles under your own Last.fm account. Failed scrobbles persist to a queue table on disk, so a network blip does not silently lose your listening history.

⚡WebSocket events

The client stays in sync over one WebSocket carrying state, renderers_updated and library_updated events — no polling for playback state.

📱Installable web app

The client is a mobile-first React SPA shipping a web app manifest, a service worker and iOS standalone metadata, so it can be added to a phone home screen and run without browser chrome.

Administration & ops

⬆️In-app updater

The server polls an update manifest on the repo, compares the published version against its own, and on request downloads the release, builds it, and swaps itself out through an ephemeral container spawned via the Docker socket. The previous image is tagged rollback first and restored automatically if the build fails.

🎟️Update channels

Stable is the baseline — a fresh install is fully unlocked with no code. Four 4-digit codes exist purely to opt a machine into the Early Access, Beta or Internal channels; they gate release channels, not features.

💾Backup & restore

Snapshot exports of the database and DSP state as tar archives, with restores staged into a holding directory and swapped in atomically, then a clean self-restart.

🐞Bug reporter

Reports captured locally as JSON with system diagnostics attached and a retention policy of 90 days plus the 50 most recent, swept at boot and daily. Client console output can be relayed to the server for debugging.

❤️Health & guards

GET /api/healthz is the liveness probe and the image ships a HEALTHCHECK against it. Every other /api route returns a clean 503 until the database is ready, with the chown hint in the body rather than a stack trace.

🗃️One data directory

The database, DSP profiles and impulse responses, cover-art and artist-logo caches, and backups all live under a single bind-mounted directory. Back that up and you have backed up the server.

Updating

    
After the first install, updates happen in the app:
    Settings → Check for updates. The server polls the update
    manifest on the repo’s main branch, compares the
    published version against its own, and on request downloads the release and
    restarts itself. The Docker socket mount above is what makes that possible.
    You should not need to run docker build a second time.


    

      Upgrading from v1.1.3.7 or earlier takes one manual step. The move
      to this repo’s manifest shipped in v1.1.3.8, so a server still on
      an older build cannot learn about it from the update it has not taken yet
      — it keeps polling the old Dropbox link and reports that it is up to
      date. Point it here once by adding
      -e MUSICD_MANIFEST_URL=https://raw.githubusercontent.com/meltface-80/MusicD-Server-v1/main/manifest.json
      to your docker run, restart, then Check for updates.
      The older parser understands this manifest, so it installs normally. Drop
      the variable afterwards — v1.1.7.0 has the same URL as its own
      default.

Stack

    
CommonJS Node 20 on Express, better-sqlite3,
    ws, node-ssdp, sharp and
    music-metadata, shelling out to ffmpeg,
    loudgain and fpcalc. The client is a React 18 +
    Vite SPA served as static assets. Three-stage Docker build on
    node:20-trixie-slim, so native modules compile against the same
    glibc the runtime uses.
