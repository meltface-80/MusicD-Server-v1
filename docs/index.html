MusicD

A self-hosted music server for one library and one home network

MusicD Server scans your albums into SQLite, folds your Qobuz and Tidal favourites in beside them, serves a fast, dense mobile-first web app, and plays the lot to DLNA / UPnP, Sonos, Squeezelite and local USB DACs — with parametric EQ, AutoEQ presets, FIR convolution and a per-stream signal path you can actually read.

v1.1.42.0 Node 20 · Express · SQLite React SPA · PWA Docker · port 32700 MIT licence

What’s new in 1.1.42.0

Your own keys for the two shared ones, a matcher that no longer gets stuck when MusicBrainz has a bad minute, bigger text throughout, and composers for your classical albums.

Changed

⚊ListenBrainz removed

Added a few releases ago to speed up the first album match, and withdrawn because it was not worth what it cost to set up. Getting a token meant finding your way around a family of sites that issue three different credentials all called a token — two of which look plausible and neither of which works.

What it saved was about forty minutes of background work the overnight scheduler does while you are asleep, once. Match quality was identical either way. Nothing else changes: matching still works from artist and title, still borrows a barcode from Qobuz or Tidal, and still fingerprints the audio for whatever text cannot place.

It never touched scrobbling — MusicD only ever asked ListenBrainz “what record is this?” and never sent them a listen. Last.fm is unaffected. Anything you typed into the token field is deleted on the next start.

New

🔑Your own keys, if you want them

MusicD ships with working keys for the services it pulls artwork and biographies from, so there is nothing to set up. Two of those keys are counted per key rather than per install — so every MusicD in the world draws on one allowance.

TheAudioDB is the one worth knowing about: the built-in value is the service's public test key, the one they hand out for trying the API, and it is throttled to match. It fetches artist images, artist biographies and album biographies. fanart.tv, used for artist logos, is a real project key but still a shared one — and a personal key also makes newly-uploaded logos visible before they are approved.

Both are now optional fields under Settings → Metadata, both free to obtain, and both leave today's behaviour exactly as it is if you skip them. Neither is ever sent back to the browser once saved.

Last.fm and AcoustID are deliberately left alone: they count per network address rather than per key, so your install already has its own allowance however many other people are running MusicD.

Fixed

🚫The matcher no longer gets stuck on one album

Album matching worked through a queue of everything not yet identified — and an album that failed stayed in that queue, so the next thing it picked up was the album it had just failed on.

Most of the time you would never see it: a one-off timeout, one retry, done. But when MusicBrainz was unreachable or asking us to slow down, every album failed — and a scheduled run became the same album over and over for a full hour, hammering a service that was already asking for a rest. If you ever saw the matcher report something like “4,312 of 2,000”, that was this.

Related: when MusicBrainz says “come back in ten seconds”, MusicD now waits ten seconds instead of treating it as a failure. And the three parts of the app that talked to MusicBrainz each kept their own timer, so a library scan running alongside a match could send three requests a second where one is allowed. There is one queue now.

New

⚡Two more ways to identify an album

If you are signed in to Qobuz or Tidal, those catalogues now help identify your own files: MusicD looks up the barcode of an album the text search could not place, and a barcode turns a guess into a certainty. It refuses to answer unless the artist, the album title and the track count all agree.

Anything that still cannot be named from text is now fingerprinted from the audio itself — something MusicD could always do, but only if you asked it to, one album at a time. It runs last, on the handful of albums nothing else could place.

UI

🔍Bigger text, and more albums on screen

Two in every five text sizes in the app were 11 points or smaller. That is the cramped feeling, measured — and it is why raising one screen at a time never fixed it. Everything has moved up a step and nothing is smaller than 11 points now.

The album wall got denser at the same time: still three across on a phone, but five on a tablet held upright, seven on its side, and nine on a desktop. Artists follow. A long album title no longer stretches its column wider than the rest of the row.

The Now Playing screen used to be painted on a deliberately darker set of surfaces than the rest of the app — a hi-fi software habit that made MusicD read as two apps with a visible seam between them. It is the same room as everything else now.

New

🎼Composers, for classical albums

A classical album is usually a title like Beethoven: Symphonies 5 & 7 over eight tracks called I. Allegro con brio — which tells you almost nothing. MusicBrainz keeps the composition as a thing in its own right, separate from any recording of it, so it can say that track is the first movement of Symphony No. 5 in C minor, Op. 67, and who wrote it.

MusicD now collects that in the background, classical albums first. It works from identifiers already sitting in well-tagged files — five of which MusicD had been reading and throwing away on every scan.

Fixed

🎨Artwork stops asking the same question forever

Cover art was the one background job with no memory of having tried. An album with no artwork anywhere — a bootleg, a private pressing, a folder of loose files — was looked up again on every single cycle, for as long as the server ran, and that queue never emptied.

It remembers now, and tries again after a week, then a month, then leaves it alone. Artwork does get added later, so never asking again would be wrong too. Fetch missing artwork still checks everything on demand.

It also stopped throwing away work: having identified an album, MusicD used to forget that and search for the artwork by artist and title all over again. It now asks for the artwork of the record it already knows about.

Fixed

⚡Reopening the app keeps the screen you left

iOS throws away a backgrounded app's web view, so reopening MusicD is a real cold start — and the Home screen showed it. The counters read zero, the carousels were missing altogether, then they appeared empty, then they filled in. Four paints, three of them wrong, and the page jumping twice as it grew.

It now remembers the Home screen it last drew and puts that up on the first frame, before anything touches the network. Fresh data still arrives a moment later and still brings in whatever you have added — but only the parts that actually changed are redrawn, so reopening with nothing new looks like the app was never closed. Nothing is served stale from the server; this is one screen remembering what it showed, not a caching policy.

New

❤️A heart next to Play

The album favourite is a button in the action row now, on every album — local, Qobuz and Tidal alike. Hollow when it is not a favourite, filled red when it is. It used to be a row inside the ⋯ sheet, two taps away.

On a Qobuz or Tidal album the ⊕ sits beside it, and the two mean different things: the heart is MusicD's own favourite, the ⊕ adds the album to your favourites at the service. The heart never touches your Qobuz or Tidal account.

Changed

📏An album header that lines up

The artwork sits higher — there was a wide empty band above it for no reason. The album title now starts level with the top of the cover instead of floating in the middle beside it, and Play sits at the bottom of that column, level with the bottom of the cover.

The title and the action row are the two ends of the same column, so the header holds together whether the album is called BE or something four times as long.

Fixed

🎯Album matching, and the sum that was wrong

An album whose artist and title were both exactly right did not match. The scoring gave 50 for the title and 30 for the artist against a threshold of 85, so a perfectly tagged record scored 80 and went to the Unmatched page — unless the year agreed too. A remaster is tagged with the remaster's year while the album's real date is the original's, so the albums most in need of help were the ones guaranteed not to get it.

Artist and title agreeing is now enough on its own. Matching also resolves the artist first and then reads their actual discography, so “The Rolling Stones” against “Rolling Stones” stops costing you every album they made — and it uses fewer lookups than before, not more.

New

📚One tile per album, not one per copy

If you own Moon Safari, Moon Safari (Deluxe) and Moon Safari (Remaster), that is three tiles for one record. Switch on Group album versions in Settings → Library and they become one — the best quality copy you own — with the others listed on its page.

Nothing is merged or deleted. It changes how the library is shown, not what is in it, and turning it off brings every version straight back. It applies to the album wall and artist pages; Favourites, Saved and search still show each version, because there you picked a particular one.

Fixed

🛠️Tidier than it was

Qobuz and Tidal favourites are no longer capped at 5000. The sync stopped there and reported 5000 as the total, so a bigger library synced part of itself and said it had finished.

The streaming album grids match the main library — they were drawing their own tiles, at two different heights depending on whether the service reported a quality, so the rows came out ragged. And Play and Add Queue sit side by side on every screen: they were being spread to the edges of their row, which only looked right on a phone.

New

☁️Qobuz and Tidal, in the same library

Sign in under Settings → Services — Qobuz with your email and password, Tidal with a code you approve at their site — and whatever you have favourited there appears in your album wall next to your own records. Sorted with them, filtered with them, searched with them.

Not a second tab and not a separate browser. The same album page, the same queue, and the same DSP chain on the way out: a Qobuz album plays to a Sonos zone with your EQ and your levelling on it, because by the time the audio reaches that pipeline there is nothing left to tell it apart from a local file.

New

➕One button decides what you keep

Every Qobuz and Tidal album page has a ⊕ beside Add Queue. It adds the album to that service's favourites — the same list their own app shows, on every device you use it from — and that is also what brings the album into the library here. Tap it again and it leaves.

The heart next to it is unchanged. It is still this app's own favourite, working on a streaming album exactly as it does on a local one. The two are kept apart on purpose: un-hearting something here should never quietly remove it from your Qobuz account.

New

🔍Search the catalogues, not just your shelf

One search box and one list of results: your own albums and tracks first, then anything matching in the catalogues of whichever services you are signed in to — the whole catalogue, not only what you have already added. Each result carries a small mark so you know which is which before you tap.

Qobuz and Tidal also get their own entries in the side menu, below Genres, showing the page types their apps do: New Releases, Favourites, Recent, and for Qobuz all eight of their editorial Browse lists.

Changed

🎪The DSP page, tidied

Every category — Volume levelling, Headroom, FIR Convolution, Parametric EQ and AutoEQ — is a heading with its switch on the right. Switch one on and it opens; switch it off and it folds away, so the page shows what you are using rather than everything at once. The zone picker sits at the top, above everything it governs.

AutoEQ has moved onto this page, at the bottom. It always edited a zone's EQ, so it belongs with the rest of that zone's chain — and it no longer carries a second zone picker that could point somewhere other than the EQ it was about to overwrite. Loading a preset now refreshes the Parametric EQ section above it, which used to keep drawing the curve the preset had just replaced.

Changed

🔊Volume levelling is per zone

It was one setting applied to every zone at once, sitting on the Settings page above everything that was already per zone. It is part of each zone's DSP now, with its own category at the top of the page.

Nothing changes when you update. Every zone carries on doing exactly what it did until you change one of them — and it works on Sonos too, which bypasses the EQ but can still be levelled, because levelling is a gain applied before the encoder rather than part of the filter chain.

New

☑Tick albums, play the lot

A Select chip on the Albums wall, Favourites, Saved for later and the Random wall. Tap tiles to pick them, then choose what happens: Play now, Play next, Add to queue, Shuffle play or Save for later — the same options the album page has, in the same order.

Everything plays in the order you ticked it, whole albums at a time. While you are choosing, the sort and filter chips step aside and the Random wall hides its Refresh — re-sorting or re-rolling would throw your selection away with nothing to get it back.

New

🎨Four themes

Dark and Light, plus Copper — the colours from the MusicD site — and Brass, copper in daylight. Settings → Appearance, below Backup. Each row in the picker previews its own palette rather than describing it.

The choice is kept per device, not on the server: a phone at night and a desktop in daylight want different answers, and one shared setting would force them to agree.

New

🏠A Home screen you choose the shape of

Recently added and Recently played are two carousels now instead of one row behind tabs, so you can see both at once. A third shows albums at random — tap its heading for a full page of them with a Refresh button.

All three have switches in Settings → Home Screen, above a line separating them from the music-news sources. They read your own library, so they are on by default and cost nothing outside your network. The library counters stay at the top either way.

Features

One server, one library, one home network. Everything below runs on your own hardware and talks to nothing you did not ask it to.

Streaming services

☁️Qobuz & Tidal

Sign in under Settings → Services to either or both. Qobuz takes an email and password; Tidal uses a device code you approve at their site.

Your favourites at each service become part of the same library as your own files — one album wall, one set of Focus filters, one search that reaches both catalogues in full rather than only what you have already added. A ⊕ on any streaming album page adds it to that service's favourites, which is also what keeps it here.

Streaming tracks go through the same pipeline as local files: levelling, PEQ, convolution, per-renderer downsampling, dither and FLAC encoding. Quality is whatever tier you pick, converted per zone only where a renderer cannot take it.

Playback & formats

🎵Codecs

Scanned and played straight from disk:

  • Lossless — FLAC, WAV, AIFF, ALAC (.m4a), WavPack (.wv)
  • Lossy — MP3, Ogg Vorbis, Opus, AAC (.m4a)
  • DSD — .dsf, .dff, .dsd

FLAC, MP3 and WAV pass through untouched when nothing in the chain needs to alter them — no volume levelling, no DSP, no downsample.

〰️DSD handling

DSD bitstreams are decoded by FFmpeg and resampled to 176.4 kHz PCM — the highest 44.1-family integer multiple at or below 192 kHz. Going to 192 kHz would force a 44.1 ↔ 48 conversion, which is audibly worse, and 176.4 stays inside the bandwidth ceiling of every renderer that matters.

Local ALSA output additionally has a per-DAC DSD mode setting.

📶Gapless

The next track is pre-queued on the renderer through the UPnP-standard SetNextAVTransportURI while the current one is still playing, and the queued target is cleared on a skip so it cannot leak into the new selection.

📉Volume levelling

Per-track and per-album loudness normalisation against a configurable LUFS target (default −18 LUFS), analysed with loudgain (libebur128) and falling back to FFmpeg. Existing R128 tags are honoured with their own reference level.

🌡️CPU thermal throttling

Background loudness and metadata jobs back off against a user-configured CPU temperature ceiling (default 65 °C), read from the host’s /sys/class/thermal with sensor selection across x86_pkg_temp, coretemp, k10temp and cpu_thermal.

📻Radio mode

When the queue runs dry, radio mode keeps going instead of stopping, with a short history so it does not immediately repeat itself.

Renderers & zones

🛰️DLNA / UPnP

Any AVTransport renderer, auto-discovered over SSDP. This is the widest-compatibility path and the one DSP applies to.

🎶Sonos

Native integration built on raw SOAP, topology-aware since 1.1.3.8 so pairs, bonded subs and surrounds, and app-side groups each appear once. An optional 16-bit force mode exists for stubborn zones, using triangular (TPDF) dither on the way down.

🔗Squeezelite / LMS

Squeezebox sink discovery and control, with an optional Lyrion Media Server bridge configured through LMS_HOST and LMS_PORT. DSP applies here too.

🎧USB DAC via ALSA

Local output with capability detection, per-device DSD mode, and a DSP bypass that is on by default so a DAC doing its own processing is not doubled up. Capabilities are probed lazily via aplay --dump-hw-params when /proc/asound is not available.

🏘️Multi-zone

Each zone is one renderer with its own queue, position and volume, all running at once. The UI focuses one zone at a time; the others keep playing. Per-zone queue and position survive a server restart.

DSP

🎛️Parametric EQ

Biquad bands per profile — peaking, low shelf and high shelf — compiled into an FFmpeg filter chain per stream. Profiles are assigned per renderer, so your headphone amp and your living-room speakers do not share an EQ.

📚AutoEQ presets

A starter set of 22 headphone presets ships in the image. One action in Settings pulls the full AutoEQ parametric database — thousands of measured models — straight from the upstream AutoEq project and rebuilds the local index.

🌀FIR convolution

Upload impulse-response WAVs, one per supported sample rate, with independent dry and wet gain. Malformed IRs are rejected with an actual explanation rather than silence.

🎚️Crossfeed & headroom

Crossfeed profiles cmoy, meier and jmeier via bs2b, plus a manual headroom slider from −12 dB to 0 dB (default −3 dB) at the end of the chain.

🛡️Auto-preamp

The maximum gain the PEQ chain can apply is computed when the profile is saved and negated into a preamp, keeping peaks at or under 0 dBFS without you doing arithmetic.

🔁Chain order

Fixed and inspectable:

  • source → auto-preamp → PEQ
  • → convolution → crossfeed
  • → downsample → dither

DSP is applied for DLNA and Squeezelite renderers. Sonos zones keep their stored profile but are not processed, because Sonos runs its own EQ.

Signal path

🔍Per-play signal path

A Roon-style chain is built for every play and pushed to the client with the rest of the player state, reachable from the orb in the full-screen player. It shows what actually happened to the stream on the way to that specific renderer — decode, EQ, resampling and the renderer itself — rather than what the file claims on disk.

🚚Transcoding & streaming

A real-time FFmpeg pipeline downsamples to the renderer’s maximum supported rate, dithers on bit-depth reduction, and reports the chosen output rate back on the response. Diagnostic headers are ASCII-sanitised so a stray em dash cannot kill the stream mid-play.

Library, search & Focus

🗂️Scanning

Auto-scan on startup plus a filesystem watcher, which polls by default because inotify does not propagate across Docker bind mounts and NFS / SMB shares. Multi-disc albums are flattened — CD1, CD2, Disc 2 folders group into one album.

🔎Search

SQLite FTS5 across title, artist, album and genre, indexed in the same database as everything else.

🎯Focus filters

Roon-style include and exclude pills, ANDed across sub-sections and ORed within one:

  • Format, genre, decade, artist
  • Bit depth, sample rate, channel count
  • Last played, added on

Combinations you keep reaching for can be saved and re-applied.

🏷️Tags & bookmarks

User tags with hex colours, applied to albums and tracks, plus a save-for-later flag on both that is deliberately separate from tags — it is a pinned bookmark, not a label.

Metadata & discovery

🖼️Cover art

Embedded artwork and folder images (cover, folder, front…) first, then Cover Art Archive via the matched MusicBrainz release. Results are cached on disk and in a bounded in-memory LRU.

🧬MusicBrainz & AcoustID

Album and artist matching against MusicBrainz release-groups, run by a scheduler and throttled to the 1 req/s their terms require. For files too poorly tagged to match, fpcalc generates an acoustic fingerprint and looks it up against AcoustID.

✍️Bios & logos

Artist biographies from Last.fm, cached locally. Artist logos come from a waterfall — MusicBrainz ID, then fanart.tv, then TheAudioDB, then a typographic SVG rendered on the server so there is always something to show.

📰Music news

An in-app feed built from Pitchfork’s RSS channels plus Qobuz Magazine and Bandcamp Daily, rate-limited so a client stuck in a refresh loop cannot hammer anyone’s server.

Sharing & integrations

🪪Share cards

1200 × 600 PNGs rendered server-side from SVG with sharp — one for the current track, one for any album. Shared from the full-screen player or an album page through the system share sheet.

📊Last.fm scrobbling

Per-zone now-playing updates and scrobbles under your own Last.fm account. Failed scrobbles persist to a queue table on disk, so a network blip does not silently lose your listening history.

⚡WebSocket events

The client stays in sync over one WebSocket carrying state, renderers_updated and library_updated events — no polling for playback state.

📱Installable web app

The client is a mobile-first React SPA shipping a web app manifest, a service worker and iOS standalone metadata, so it can be added to a phone home screen and run without browser chrome.

Administration & ops

⬆️In-app updater

The server polls an update manifest on the repo, compares the published version against its own, and on request downloads the release, builds it, and swaps itself out through an ephemeral container spawned via the Docker socket. The previous image is tagged rollback first and restored automatically if the build fails.

🎟️Update channels

Stable is the baseline — a fresh install is fully unlocked with no code. Four 4-digit codes exist purely to opt a machine into the Early Access, Beta or Internal channels; they gate release channels, not features.

💾Backup & restore

Snapshot exports of the database and DSP state as tar archives, with restores staged into a holding directory and swapped in atomically, then a clean self-restart.

🐞Bug reporter

Reports captured locally as JSON with system diagnostics attached and a retention policy of 90 days plus the 50 most recent, swept at boot and daily. Client console output can be relayed to the server for debugging.

❤️Health & guards

GET /api/healthz is the liveness probe and the image ships a HEALTHCHECK against it. Every other /api route returns a clean 503 until the database is ready, with the chown hint in the body rather than a stack trace.

🗃️One data directory

The database, DSP profiles and impulse responses, cover-art and artist-logo caches, and backups all live under a single bind-mounted directory. Back that up and you have backed up the server.

Updating

    
After the first install, updates happen in the app:
    Settings → Check for updates. The server polls the update
    manifest on the repo’s main branch, compares the
    published version against its own, and on request downloads the release and
    restarts itself. The Docker socket mount above is what makes that possible.
    You should not need to run docker build a second time.


    

      Upgrading from v1.1.3.7 or earlier takes one manual step. The move
      to this repo’s manifest shipped in v1.1.3.8, so a server still on
      an older build cannot learn about it from the update it has not taken yet
      — it keeps polling the old Dropbox link and reports that it is up to
      date. Point it here once by adding
      -e MUSICD_MANIFEST_URL=https://raw.githubusercontent.com/meltface-80/MusicD-Server-v1/main/manifest.json
      to your docker run, restart, then Check for updates.
      The older parser understands this manifest, so it installs normally. Drop
      the variable afterwards — v1.1.42.0 has the same URL as its own
      default.

Stack

    
CommonJS Node 20 on Express, better-sqlite3,
    ws, node-ssdp, sharp and
    music-metadata, shelling out to ffmpeg,
    loudgain and fpcalc. The client is a React 18 +
    Vite SPA served as static assets. Three-stage Docker build on
    node:20-trixie-slim, so native modules compile against the same
    glibc the runtime uses.
